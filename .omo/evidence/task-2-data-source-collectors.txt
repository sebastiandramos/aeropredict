# A) THE BUG (found, root-caused)
############################################################
storage_silver.py:473 and :510 called `col.create_index("_id", unique=True)`.
MongoDB rejects this because `_id` is ALWAYS unique by default; the `unique`
option is not valid for an `_id` index specification:

    OperationFailure: The field 'unique' is not valid for an _id index specification

Fix applied (both places): `col.create_index("_id")` (drop `unique=True`).
The `_id` index remains unique by MongoDB semantics; `_id` = `ident` (airports)
and `f"{airport_ident}:{le_ident}:{he_ident}"` (runways) is preserved.
The write_aircraft pattern (:321) is untouched: it indexes `icao24` (a NON-_id
field), so its `unique=True` is correct.
